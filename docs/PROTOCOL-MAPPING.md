# ACP ↔ Pi protocol mapping

This document specifies the translation contract. Exact TypeScript names must be updated to the pinned SDK, but semantics should remain covered by fixtures.

## 1. Handshake

Client initialize request:

```json
{
  "protocolVersion": 1,
  "clientInfo": {
    "name": "pi-gemini-acp-provider",
    "title": "Pi Gemini ACP Provider",
    "version": "<package-version>"
  },
  "clientCapabilities": {
    "fs": { "readTextFile": false, "writeTextFile": false },
    "terminal": false
  }
}
```

Use the SDK's current shape; the JSON above expresses intended posture. Omit unsupported capabilities if the schema prefers omission over false. Validate returned protocol version, agent info, auth methods, and prompt/MCP capabilities. Unknown fields are retained in diagnostics but do not fail initialization.

Do not advertise fs, terminal, or other handlers merely because Gemini supports calling them. NDJSON frames can contain base64 images and large tool/diff content on one line: use a chunked decoder with an explicit initial 32 MiB maximum frame/partial-line limit (configurable only within a hard ceiling), reject oversized input, and never use a small default line reader.

## 2. Session creation

Before creating a chat session, start the authenticated loopback Pi-tool MCP server and prepare its descriptor. Initial v1 request:

```json
{
  "cwd": "/absolute/canonical/workspace",
  "mcpServers": [
    {
      "name": "pi-tools",
      "type": "http",
      "url": "http://127.0.0.1:<ephemeral>/mcp",
      "headers": [{ "name": "Authorization", "value": "Bearer <memory-only-token>" }]
    }
  ]
}
```

The exact descriptor shape is SDK-version dependent and must come from pinned types. Beta provider-only probes may use `[]`; a 1.0 chat binding may not if compatible Pi tools are active.

Validate:

- non-empty string session id;
- model ids are bounded printable strings with no control characters;
- names/descriptions have size limits;
- current model is in available list or represented as an additional validated entry;
- mode ids/options are similarly bounded.

Do not pass `tools.core: []` or modify global Gemini configuration. MCP descriptors are generated by the provider and use loopback URLs and memory-only secret headers.

## 3. Prompt content mapping

### Current user message

| Pi input | ACP content |
|---|---|
| string | `{type:"text", text}` |
| text block | `{type:"text", text}` |
| image block | `{type:"image", data, mimeType}` if advertised |
| unsupported image | visible stream error; do not silently drop |

Preserve user block order where meaningful. For Gemini's resolver and contextual clarity, provider-added reconstruction resource goes before final user text. Enforce total/base64 size limits before spawn/write.

### System prompt and history

ACP v1 prompt has no independent Pi-equivalent system role. On a fresh binding, create a provider-owned embedded resource such as:

```json
{
  "type": "resource",
  "resource": {
    "uri": "urn:pi:gemini-acp:context/<session>/<revision>",
    "mimeType": "text/markdown",
    "text": "...bounded reconstruction..."
  }
}
```

Only use it when `promptCapabilities.embeddedContext` is advertised; otherwise prepend a clearly delimited text section. Never resend it unchanged to a warm session.

### Pi tool results

- Permission broker result: consumed by the provider; not sent as a new Gemini user prompt.
- Pi-tool MCP bridge result: resolves the parked MCP call; not sent through `session/prompt`.
- Ordinary Pi result unknown to the live ACP session: include in the next bounded external-context delta.

## 4. Session update mapping

### Message chunks

`agent_message_chunk` with text content:

1. Close an open thinking block.
2. Ensure Pi `start` has been emitted.
3. Open text block with `text_start` if needed.
4. Append and emit `text_delta`.

Images/resources in agent message chunks are unsupported by Pi assistant model output unless Pi adds a matching block. Preserve a diagnostic and add a textual link/description only if semantically safe; never cast to text blindly.

### Thought chunks

`agent_thought_chunk` with text content:

1. Close text block.
2. Ensure `start`.
3. Open `thinking_start`.
4. Append `thinking_delta`.

Do not invent hidden chain-of-thought. Forward only the thought summary text Gemini ACP explicitly emits. Redact nothing except secrets accidentally present in diagnostics; user-visible content should remain faithful.

### Tool calls and updates

Maintain a per-turn map keyed by ACP `toolCallId`:

```ts
interface ToolActivity {
  title: string;
  kind?: string;
  status?: "pending" | "in_progress" | "completed" | "failed";
  locations: string[];
  rawInput?: unknown;
  content: unknown[];
}
```

Default v1 rendering:

- `tool_call`: close text, append a concise thinking line (`[Gemini tool: title — status]`).
- `tool_call_update`: append only changed status/output; render diff content with bounded unified-diff formatting; do not dump raw input/output by default.
- completion/failure: update the line/block; preserve structured activity in message diagnostics if Pi's diagnostic type allows bounded JSON.

Never emit a Pi executable `toolCall` for a Gemini tool that Gemini has already or will execute. The exception is provider-owned permission/MCP round trips, where Pi is intentionally the executor/decision maker.

This means Gemini-native tool operations are not represented as Pi `ToolCall`/`ToolResultMessage` pairs. A later provider receives final assistant text and bounded activity summaries, not a lossless structured record of those operations. In contrast, bridged Pi/marketplace tools do produce normal Pi tool history. Namespace bridged names as `pi_<name>` (with a reversible collision-safe encoding). Pi hooks/policies apply to those bridged calls, not to similarly named Gemini-native calls; Gemini-native mutating calls still require the ACP/Gemini permission policy. Cross-provider tests must validate both cases and documentation must not claim full structured parity for Gemini-native tools.

### Plans and commands

- Plan chunks: thinking blocks, unless ACP explicitly marks final user-facing text.
- Available command updates: runtime diagnostics only; do not register arbitrary Pi commands at turn time.
- Current mode/model updates: update binding after validation; no text unless it contradicts selected Pi state.
- Unknown updates: ignore safely and count/log type at debug level.

## 5. Permission request mapping

ACP agent request:

```text
session/request_permission(requestId, sessionId, toolCall, options[])
```

Provider action:

1. Validate session/generation and option uniqueness.
2. Generate opaque broker id; retain exact offered `optionId`s.
3. Produce Pi provider-owned tool call:

```json
{
  "type": "toolCall",
  "id": "gemini-permission-<opaque>",
  "name": "gemini_acp_permission",
  "arguments": {
    "requestId": "<opaque>",
    "title": "Run shell command",
    "kind": "execute",
    "locations": ["..."],
    "summary": "...",
    "choices": [
      { "id": "display-token", "label": "Allow once", "kind": "allow_once" },
      { "id": "display-token", "label": "Reject", "kind": "reject_once" }
    ]
  }
}
```

Do not expose raw ACP option ids if avoidable; map opaque display tokens to retained ids. The permission tool must be excluded from the MCP tool list. If Pi cannot hide it from other providers' `context.tools`, its execute function returns a harmless error unless an exact pending broker record matches; visibility is then a documented host limitation, not an approval path. The permission tool returns a signed/validated structure or a simple selected display token in `details`. The provider consumes it on continuation and returns:

```json
{ "outcome": { "outcome": "selected", "optionId": "<offered-id>" } }
```

Cancel/timeout/headless returns:

```json
{ "outcome": { "outcome": "cancelled" } }
```

Pi stream around permission:

```text
... optional text_end/thinking_end
→ toolcall_start
→ toolcall_end
→ done(reason: "toolUse")
```

Next provider call resumes the existing ACP prompt and begins a new Pi assistant stream. Multiple permissions are supported serially. Stale/replayed tool results are rejected and cannot approve another request.

## 6. Final response mapping

### Stop reasons

| ACP `PromptResponse.stopReason` | Pi | Additional fields |
|---|---|---|
| `end_turn` | `stop` | `endTurn: true`, `rawStopReason` |
| `cancelled` | `aborted` | terminal `error` event, raw reason |
| `max_tokens` | `length` | terminal `done`, raw reason |
| `max_turn_requests` | `length` | terminal `done`, diagnostic distinguishes turn limit |
| unknown non-error | `stop` only if SDK classifies normal; otherwise `error` | always preserve raw |
| JSON-RPC/process/protocol error | `error` | redacted `errorMessage` |

Check Pi conformance behavior for `length`; a truncated generation is a completed assistant response, so use `done(reason:"length")`, not transport error.

### Usage

Parse current extension shape with strict numeric validation:

```text
input  = quota.token_count.input_tokens   ?? 0
output = quota.token_count.output_tokens  ?? 0
cacheRead = 0
cacheWrite = 0
totalTokens = input + output
reasoning = undefined (unless upstream exposes separate count)
cost totals = 0
```

Reject negative, non-finite, fractional, or unsafe integer values into diagnostics and use zero for that field. Do not derive tokens from text length. Keep `model_usage` as bounded diagnostics and use it to set `responseModel` when unambiguous. Auto-routing may involve more than one model, in which case retain all and do not pretend one id produced everything.

Dollar cost remains zero because CLI subscription/API-key routing and model-specific billing cannot reliably be inferred from ACP metadata. README should label zero as “not reported,” not “free.”

## 7. Pi event writer state machine

State:

```text
started: boolean
open: none | text(index) | thinking(index)
terminal: boolean
partial: AssistantMessage
```

Rules:

- `ensureStart()` at most once.
- `openText()` closes thinking; `openThinking()` closes text.
- Delta cannot occur before corresponding start.
- Close emits authoritative accumulated content.
- Tool round trip closes any open block first.
- Finalize closes open block and emits exactly one terminal event.
- Setup errors may emit direct `error` before `start` if Pi permits; choose one consistent tested policy.
- Ignore all late activities after terminal/generation invalidation.

Empty successful responses should still emit `start`, an empty text block start/end if required by Pi tests, and `done`, rather than hanging or creating invalid content.

## 8. Cancellation mapping

Abort procedure:

```text
AbortSignal fires
  → mark turn aborting (mapper drops subsequent normal updates)
  → cancel all pending permissions
  → notify/request session/cancel
  → wait cancelGrace
  → if PromptResponse(cancelled), finalize aborted and keep process if healthy
  → else abort SDK RPCs, close pipes, kill process group, mark binding dead
  → finalize Pi error(reason: aborted)
```

Race handling:

- If normal completion wins before abort is observed, complete normally.
- If abort wins, no later `done` or delta is allowed.
- A cancel RPC `method not found` immediately triggers teardown fallback.
- A child exit settles every request and stream exactly once.

## 9. Error classification

| Class | Example | User action / recovery |
|---|---|---|
| `auth` | ACP `-32000`, missing key | `/login gemini-acp`; process can be replaced |
| `model` | unsupported model id | refresh models/select available model |
| `rate_limit` | 429 | retry later; no automatic account rotation |
| `protocol` | malformed JSON/response | show versions; kill process; file bug |
| `startup` | entry missing/early exit | reinstall/doctor; no PATH advice by default |
| `timeout` | handshake/prompt idle | cancel then kill; include phase |
| `permission` | no valid options/stale result | deny and report |
| `filesystem` | denied path/ENOENT | bounded safe message |
| `aborted` | user cancel | no alarming error wording |
| `internal` | invariant violation | kill affected generation; report issue id |

Messages must not include API keys, OAuth tokens, full environment, unredacted headers, full prompt, or arbitrary stderr. Attach a short correlation id for opt-in debug logs.

## 10. Pi tool schema projection

Pi exposes TypeBox/JSON-schema tool definitions, while Gemini's function declaration subset may reject valid constructs such as complex unions, pattern properties, recursive references, symbols/custom validators, or unsupported formats.

Projection rules:

1. Project a conservative JSON-schema subset; inline local `$ref` definitions from the root `$defs`/`definitions` (including TypeBox `Cyclic` bare-name references); reject recursive or remote references and other unsupported keywords, including when nested, rather than dropping their constraints.
2. Preserve object properties, descriptions, required lists, scalar `enum`/`const` values (including false, zero and null), primitive/array/object shapes, and supported numeric/string/collection constraints. Add a singleton enum alongside a const for consumers which ignore const.
3. Preserve supported `additionalProperties` constraints, and project a single catch-all `patternProperties` (TypeBox string-keyed `Record`) without sibling `properties`/`additionalProperties` as `additionalProperties`. Keep empty/typeless nested schemas as supplied; never infer a contradictory type or silently widen a constrained schema.
4. Reject executable/custom validators, proxies, accessors, unsafe property names, malformed keyword values and cycles. Bound schema depth to 16, traversal work to 100,000 visits/keys/elements, and projected JSON to 64 KiB per tool. Drop non-scalar annotation defaults without traversing them.
5. Omit rejected tools from MCP `tools/list`, record tool name plus a stable reason in diagnostics, and warn once in UI. Never let one marketplace schema fail the whole Antigravity session.
6. Validate MCP call arguments again against the original Pi schema before emitting the Pi tool call; the projected model schema is not the authorization boundary.
7. Synthetic MCP tests exercise advertised schemas, original argument validation and rejection of hostile schemas. Compatibility of every projected keyword with live Google inference is not implied by these tests.

## 11. Compatibility rules

- Protocol parsing is tolerant of unknown additive fields/updates.
- Required identifiers and terminal responses are strict.
- Method fallback is explicit and version tested, never guessed from error strings except standardized JSON-RPC code `-32601`.
- History replay is suppressed only during a known `session/load` operation and scoped to its session; never globally suppress live updates.
- Every captured fixture records CLI version, SDK version, OS, and expected mapping.
